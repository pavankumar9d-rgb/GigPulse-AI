# GigPulse AI — UI/UX Direction

## Target interpretation
The supplied target screenshot is a premium mobility operations dashboard: black/graphite canvas, understated surfaces, acid-lime highlights, tight but readable typography, concise charts, and a balanced modular grid. It is not a blue SaaS admin template.

## Composition
- Slim top bar; narrow icon rail; generous content canvas.
- Use a 12-column grid on desktop with deliberate asymmetric spans.
- Main content should have clear focal points rather than a uniform wall of identical KPI cards.
- Use subtle dividers and low-contrast surface shifts, not thick outlines.
- Use lime only for active states, selected data series, primary actions, and important values.
- Maintain enough contrast for small labels and chart axes.

## Component character
- Rounded but not bubbly; use restrained 12–18px radii.
- Avoid pills unless they represent a status or filter.
- Avoid large gradient backgrounds, glassmorphism, heavy shadows, and glowing borders.
- Use consistent chart styling: quiet gridlines, clean tooltips, clear legends, lime for emphasis.
- Use tabular numerals for money, hours, counts, and metrics.
- Keep helper text short and metadata visually secondary.

## Product-specific truth
The screenshot is a visual direction only. Do not transplant taxi-specific labels or fabricate map locations, speed, battery, ratings, passenger, or trip metrics. GigPulse widgets must represent its real earnings, work sessions, expenses, deliveries, demand forecasts, model evaluation, and recommendations.

## Photography
Photography is optional and secondary. Do not turn the analytics dashboard into a marketing landing page. Use at most one carefully cropped contextual image if it improves a specific panel; keep stock imagery out of KPI cards and worker identity. Prefer CSS/SVG and real data visualizations.
